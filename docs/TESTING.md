# Testing plan

Two layers: automated tests for the pure game logic, which run anywhere with Lune, and a manual multi-client checklist for everything that needs the engine. The doc's playtest ladder and fun gates (sections 10 and 12) sit on top of both.

## Automated

```sh
lune run tests/run        # 445 tests in 68 specs (about 90-150 s; 2-4 minutes while Studio runs)
lune run tests/compile    # every .luau file compiles
selene src tests          # lint: undefined globals, unused variables, shadowing…
```

The main specs (every `tests/specs/*.spec.luau` runs):

| Spec | Covers |
| --- | --- |
| `LevelGraph`, `Mansion`, `Golden`, `RoomRects`, `RoomFit`, `Rooms`, `Corridor`, `Exit` | The old house and the mansion: same seed → same layout, the fairness contract over many seeds, the old generator's houses never change (`tests/golden`), furniture out of room middles and doorway lanes |
| `HouseMetrics`, `HouseSize`, `RoomPurpose`, `Wings`, `Programme`, `HouseSearch` | The level design (docs/plans/level-design.md): metrics walked on a hand-built ring of rooms; houses sized by squad; every room's reasons and each region's kit; wings of 3–7 rooms that hold together and open from somewhere open before them, each beat what it says; the programme's deck and room lists; the search is deterministic, never worse than the first house, and kept houses meet the structural targets |
| `LockPlanner`, `Leads`, `NoteText`, `Objectives`, `Dinner` | Every lock plan is solvable (130 houses), gate kinds and keepers switched on and off, two-room producers; each key and heirloom gets a lead, notes name a room only it could be; the objective line; no place at the table within his reach |
| `Puzzles`, `Terminal`, `Breaker`, `Safe`, `MusicBox`, `Dumbwaiter`, `Circuits`, `SwitchSpots` | Every puzzle kind keeps the registry's contract (same seed, same puzzle; the screen never gets the answer; junk refused); each kind's own rules |
| `Acts`, `Pacing`, `Systems`, `Scent`, `Stalk`, `Belief`, `Guest`, `Storeys`, `NavGraph` | Acts from progress; whole runs simulated second by second (2–4 hunts for a steady squad, a stalled squad collapses, never a hunt in the first 3 minutes); Drift, the Director, Progression and Marks; heirloom scent; stalking rules; navigation |
| `Heft`, `Throw`, `Articulation`, `Push`, `Barricade`, `Feel`, `Inventory`, `ViewFrame` | Carrying with weight, throws and their first arc, doors with momentum, pushing, barricades (cover, shoves that always clear the doorway, never over 8 s), movement feel, slots |
| `Atmosphere` | Divergence is atmosphere only: never a door, item, note, station, the table or anything you carry or push |
| `BotPlan`, `RunStats`, `LobbyRules`, `Assist` | The bot's next step over real houses (walked to the dinner and out; pockets, cranks, boards and nailed chests; a failed step never offered again); the run in numbers and the finish line; the lobby's majority rule; stuck-assist's hint |

### Multiplayer robustness

- One client leaves mid-run: the run continues, their keys drop where they stood, and an empty server ends the run.
- Respawn or reset mid-run puts the character back where it was.
- A client that joins mid-run waits in the hub with the lobby panel showing "in the house".
- Two runs in a row: nothing is left over (lights, phantoms, stalker, prompts, attributes).

### Security

- Remote flooding (Ping, Drag, Push, PuzzleInput, Throw) is capped by the interval and the sliding window, and junk arguments are ignored.
- A speed exploit (raise WalkSpeed from the client's command bar) gets snapped back.
- Debug commands do nothing on live servers for user ids that aren't allow-listed.
- Clients never receive a note's text before reading it, a puzzle's answer, or a room or lock on the map nobody has seen. Keys and heirlooms appear only when their drawer, box or case is first opened.
- A throw the client claims is checked against its class and last valid state (`ThrowRejected` in Output when not); a held thing that jumps or passes through a wall is dropped (`HeldRejected`).

### Performance (doc section 7 targets, to verify)

- 60 FPS on a mid-range phone and a stable 30 on low-end devices. Try low-end mode, and watch FPS and memory in the overlay.
- Server heartbeat stays well under 16 ms with 4 players during a hunt (overlay `server heartbeat`).
- No frame spikes during generation (it runs server-side behind the loading screen).

## Playtesting

**The loop pass's finish line (2026-10-06, the owner's):** three solo runs with no F2, and after each read the Finish line in F2 `summary` or the Dossier's THE NIGHT IN NUMBERS: frightened twice in the first ten minutes with no hunt (scares in the first 10 min ≥ 2, first hunt after 10:00); never wondering what to do next for more than two minutes (longest without progress under 4:00, hints ≤ 1); looking at him never ends a hunt by itself (stare-downs 0); start to dinner under 40 minutes (F2 used 0); downs ≤ 1. F2 `botrun` (TC-123) gives the same numbers for a player who knows the plan.

Ask every tester the doc's question: *"Did it ever feel like it cheated?"* A yes means a telegraph or fairness rule is missing. For the level design (docs/plans/level-design.md) also ask: *"Did you get lost?"*, *"Did the shortcuts and going back feel good?"* and *"Was every room worth going into?"*, and note F2 `house`'s score for the runs that felt best and worst. Track the starting metrics with the `[Consensus:event]` log lines and AnalyticsService custom events: run completion, win rate, median run length, hunts per run and when acts began, how long each puzzle took, how often he tidied, and quit points.
